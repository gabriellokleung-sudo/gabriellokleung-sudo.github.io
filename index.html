Commissioning the Clinical Supply Center

Being part of the commissioning phase of the clinical manufacturing plant was one of the most exciting and challenging experiences of my career. There were plenty of long days and unexpected issues, from debugging automation systems to coordinating with different teams under tight deadlines. But that’s what made it so rewarding. I really enjoyed the fast pace and problem-solving environment, and it was incredible to see everything come together from the ground up. It gave me a real sense of pride and showed me how critical our work is to getting life-changing therapies to patients.

The birthplace of biotechnology

Working at Genentech has been an incredibly rewarding experience. I’ve been continually inspired by the dedication and expertise of my colleagues. Being part of a team that contributes to the production of drug substances for clinical trials has given me a deep sense of purpose. Witnessing the tangible impact our work has on patients' lives has been both humbling and motivating, reinforcing my passion for innovation and meaningful contribution in the field of biotechnology.

On-call support

As part of my role, I was on-call during certain weeks, which often meant handling support tickets during off-hours or weekends. Addressing these issues could be stressful at times, as it took careful analysis to identify the root cause of the problem. Occasionally, this meant quickly finding a nearby café, setting up my laptop, and diving into troubleshooting.

Despite the challenges, the process was also exciting—it tested my problem-solving skills and kept me on my toes. Successfully resolving an issue always brought a sense of fulfillment, knowing I had contributed to keeping systems running smoothly.

SDS Export Tool

Design specifications and redlines from a DeltaV export.

What it does
Reads a configuration export in the browser and writes Module and Recipe design specifications, a parameter reference, and redline workbooks that mark what changed between two versions.
How Claude helped
We wrote the Python desktop tools first, then ported them to a web app on Google Apps Script. The desktop version also builds as a Windows app.
How I checked it
The web version was held to the desktop version’s output on real configuration data: thousands of parameter traces, and redline workbooks cell by cell. A dozen automated test suites cover the logic.
Where it stands
Live as a web app, now past its hundredth version.
SDS Export Tool: a result and a pictureOne number (time saved, documents made or people using it) and a screenshot or short recording with the plant names removed.

Code Interpreter

Batch recipes, phases and control modules explained in plain language.

What it does
Parses DeltaV exports into a model of every recipe, phase class and module class. It writes execution flows in process language, reference documents and structured data, and a notebook answers questions from them.
How Claude helped
Claude helped write the parsers and the engine that turns equipment identifiers into process language. The same documents are the source for a question-and-answer notebook meant for process engineers, for example to ask what a phase waits for.
How I checked it
A verifier shares no code with the extractor: it re-reads the raw files and compares counts and expressions. An accuracy audit found and fixed cut-off text, garbled conditions and truncated tables.
Where it stands
Covers every batch procedure at one site, and feeds a question-and-answer notebook.
Code Interpreter: a result and a pictureOne number (questions answered, hours a recipe review used to take, or people asking) and a screenshot of a question and its answer with the names removed.

PLC Logic Process Mapper

A map of PLC logic for engineers who don’t read ladder.

What it does
Opens Logix project files with no vendor software, rebuilds programs, step sequences and ladder, and joins them to the DeltaV recipes that command them. A newcomer can follow one recipe step down to the rung that acts on it.
How Claude helped
We worked out the undocumented file format together, then wrote the reader for it with the Python standard library alone. Claude drafted the program descriptions, which show as unreviewed drafts until an engineer signs them off.
How I checked it
On the first controller every ladder rung was recovered, and a functional specification’s step table matched the extracted sequence transition for transition. An audit regenerated the data from source, and each build now stops if a cross-reference is broken.
Where it stands
Deployed inside the company as an early-development tool, aimed at training junior engineers. It reads saved project files, so it shows the logic, not live values.
PLC Logic Process Mapper: a result and a pictureOne number (engineers trained, or hours a handshake trace used to take) and a screenshot with the plant names removed.

How I work with AI

Claude writes much of the code. The trust comes from the checks around it.

Check it against the source
A second reader that shares no code with the tool re-reads the raw files and compares. It caught a bug that cut long text at 200 characters, which the first check had missed.
Prove the port
The web version of the SDS tool was held to the desktop version’s output on thousands of real cases. The comparison exposed defects on both sides.
Label what the machine wrote
Generated text carries a badge until a named engineer reviews it, and each link between two systems says whether it is confirmed or only a lead.
Fence the data
Raw plant exports stay out of the repositories. A script and a git hook limit what reaches each shared remote, even if I slip.

My role

I’m the lead mechatronics engineer on Drinkfill. I bridge the software and mechanical designs: I designed the overall circuitry for power and the fluidic components, and I programmed the controller that runs the machine.

With the team I designed, prototyped and iterated the machine, and we are now pushing it toward a production-grade product.

The product

Drinkfill is a smart vending machine that makes drinks fresh on the spot instead of selling them in plastic bottles. The team set four goals:

  • Zero plastic bottle waste
  • Premium, freshly made drinks
  • A fun, interactive experience
  • Smart data analysis and management

Drinkfill Mini was a proof-of-concept prototype that we built and beta-launched to collect data on engineering improvements, usability and customer behavior. We deployed 5 Minis around Greater Vancouver, including UBC, Langara College, HiVE shared office and other offices.

Wearable Airbag

This is a university prototyping project of a wearable device containing sensor technology that can inflate an airbag to reduce injury due to falling. It utilizes a gyro-accelerometer sensor to monitor the user's motion and detect falls.

The fundamental goal of this project is to create a proof-of-concept model to justify the design approach.

Type
University capstone
Sensing
Gyro-accelerometer on an Arduino UNO
Airbag
About 3 L of compressed CO2, inflates in about 600 ms
Goal
A proof of concept for preventing fall injuries
ResultWhat changed because of this work? One sentence, with a number if you have one: time saved, uptime, units built, errors avoided.

Understanding the needs

One out of five falls causes a serious injury, including broken wrist, arm, ankle and hip fractures.

More than 95% of hip fractures are caused by falling, usually by falling sideways.

Fall injuries cost more than US$50 billion in medical costs in 2015.

Proposed Design Solution

01 | To design and prototype an active airbag system to reduce fall injuries

02 | The system must not interfere with the user’s daily activities

03 | The system will be easily integrated into normal daily clothing and be concealed within

Intended users include athletes, elderly people, rehabilitation patients or other individuals that require fall injuries prevention

When designing the system, several attributes were considered and ranked to ensure our product can meet our goals and customers’ satisfaction. The most important factor is safety, as our customers will wear it on a daily basis. Reliability is our second most important attribute because our customers rely on our system to dampen the fall impact. The following attributes are related to material use, size, and user-friendliness bridging into the final marketable product.

Airbag module specifications

  • Material: Nylon & PEVA (polyethylene vinyl acetate)
  • Volume: ~3 Liters
  • Inflation Time: ~600ms (Mechanical hardware delay)
  • Gas type: Compressed CO2
  • Construction Method: Sewn and Adhesive

Shown below are the two states of the airbag module: Inflated vs Not Inflated

Fluidic adaptor module specifications

The fluidic module is used to securely position several parts that are used to inflate the airbag module. The spring-loaded ratchet adaptor that is connected to the motor shaft is used to open the valve. This valve is used for sealing the CO2 cartridge. When the valve is opened, pressurized CO2 will be released to inflate the airbag.

  • Connected Parts: Motor, Spring, Ratchet Adapter, CO2 Cartridge
  • Material: PLA
  • Construction Method: 3D printing

Pressure Sensor Implementation

My first task during the internship was to implement a pressure sensor into a DNA sequencing system. The objective was to utilize sensor data to detect when and where air entered the system during pump sequences.

I wrote a Python script to read, output, store and plot data of the pressure sensor in real time. The program utilizes Python libraries pandas, numpy and matplotlib to manage data, as well as displaying real-time animation of the readings when executed.

Shown here are the sensors; the sequencers they were fitted to are at the top of the page.

GUI for robot testing

To improve efficiency on test processes, a Python based GUI was created, which allowed test engineers to interact and control robot movements by simply clicking buttons. Before the creation of this program, test engineers had to execute movement commands through the command terminal, which was challenging for individuals who were not familiar with Linux and software programming. This program is also capable of executing sequential movements, as well as performing movements loops and saving movements sequences.
